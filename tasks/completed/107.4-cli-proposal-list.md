# Objective
Expose the indexed proposal summaries through `lifeos proposals list`.

# Dependencies
LIFEOS-107.2 and LIFEOS-107.3.

# Scope
Query the existing registry through the query service.
Support an optional lifecycle-status filter only if consistent with the existing CLI style:
```text
lifeos proposals list --status approved
```
Define deterministic output containing:
ID
STATUS
UPDATED
TITLE

Define behavior for:
* empty registry
* missing registry database
* registry without the proposal migration
* invalid `--status`
* stale index, if the registry already tracks scan freshness

Do not silently read proposal files as a fallback.

# Non-goals
* web dashboard
* interactive UI
* applying or editing proposals
* automatic lifecycle transitions

# Expected files
* `src/lifeos/cli.py` or the existing CLI command modules
* `tests/cli/test_proposals_cli.py`

# Acceptance criteria
* deterministic output
* status filter works
* empty state is clear
* missing registry produces a stable message and exit behavior
* command performs SQLite reads only
* no proposal file changes occur

# Focused test plan
* `tests/cli/test_cli.py`: Cover empty registry, invalid status filters, gracefully failing if the registry DB is missing, gracefully failing if proposals table is missing, output format, and no disk/Git access.
