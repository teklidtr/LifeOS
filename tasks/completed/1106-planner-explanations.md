# Goal

Make every adaptive recommendation understandable through stable evidence,
baseline comparisons, counterfactuals, and uncertainty rather than a single
opaque score.

# Scope

- Define typed explanation contracts for selected and rejected candidates.
- Include:
  - declared and calibrated duration
  - baseline rank and adaptive rank
  - capacity and motivation fit evidence
  - due-date, blocker, mode, and diversity effects
  - avoidance or clarification flags
  - sample counts, freshness, uncertainty, and confidence
  - ignored signals and why they were ignored
- Add **Why this?**, **Why not this?**, and **What would change the result?**
  queries through the facade and bridge.
- Add concise and expanded explanation forms for dashboard and review use.
- Ensure explanations are deterministic and serializable.
- Add privacy-aware redaction so explanations do not leak unrelated journal
  details.
- Add stable machine-readable reason codes for UI rendering and tests.

# Out of scope

- Building the Obsidian components; LIFEOS-1107 covers presentation.
- Natural-language explanations generated by an LLM.
- Exposing raw internal optimizer implementation details that are not stable
  contracts.

# Required invariants

- An explanation always matches the exact planner result and policy version.
- Baseline behavior remains visible.
- Confidence is evidence-based, not invented model probability.
- Private source excerpts are not required to explain an aggregate adjustment.
- Unsupported or unavailable evidence is named explicitly.
- Reason codes remain stable within a protocol version.

# Required tests

- Selected and rejected candidate explanations.
- Baseline versus adaptive deltas.
- Counterfactual available time, energy, motivation, and mode.
- Low-confidence, contradictory, disabled, and stale signals.
- Privacy redaction and source references.
- Deterministic ordering and JSON serialization.
- Protocol compatibility and unsupported reason codes.

# Acceptance criteria

- A user can inspect why the menu changed and what evidence would reverse it.
- Plugin code does not need to recreate planner reasoning.
- Full tests, Ruff, mypy, and diff checks pass.
