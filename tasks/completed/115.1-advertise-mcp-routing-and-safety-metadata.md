# Objective

Make the LifeOS MCP ingestion and proposal workflow reliably discoverable to
Codex through explicit server instructions and tool metadata.

# Scope

- Add concise descriptions for every exposed MCP tool.
- Add server instructions that route ingestion through source reading and draft
  proposal creation.
- Require an explicit user request before proposal lifecycle transitions.
- Advertise accurate read-only, mutating, idempotency, and destructive hints.
- Add regression tests for advertised instructions and metadata.
- Document the Codex-to-LifeOS MCP ingestion workflow.

# Non-goals

- Changing the standalone `lifeos ingest` command or AI-provider setup.
- Adding new MCP tools.
- Automatically submitting, approving, or applying a proposal.
- Changing proposal validation, authorization, or application semantics.

# Acceptance criteria

- Every MCP tool has a non-empty, workflow-specific description.
- Server instructions describe `vault_read_markdown` followed by
  `ingestion_create_wiki_proposal` and stopping at draft by default.
- Server instructions forbid lifecycle transitions without explicit user intent.
- Tool annotations accurately distinguish read-only, proposal-producing, and
  consequential operations.
- Existing MCP behavior and strict input schemas remain unchanged.
- Focused tests and repository validation pass.
