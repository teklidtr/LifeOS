# Objective
Show proposal lifecycle counts in `lifeos status`.

# Dependencies
LIFEOS-107.3.

# Scope
Use `count_proposals_by_status()`.
Use canonical proposal statuses, not task statuses such as `ready` or `in-progress`.
Choose one deterministic display policy:
`show every canonical status including zero`
or:
`show only nonzero statuses`
Document the choice and test it.
The status layer must not duplicate SQL.

# Non-goals
* listing individual proposals
* filesystem scan inside the status renderer
* proposal mutation
* task-status counts

# Expected files
* `src/lifeos/status.py`
* `tests/status/test_status.py`

# Acceptance criteria
* counts come from SQLite
* each lifecycle status is counted correctly
* empty state is correct
* output order is deterministic
* no proposal filesystem access occurs

# Focused test plan
* `tests/status/test_status.py`: Verify that the existing `status` command retrieves the SQLite counts cleanly, aggregates them into the deterministic display policy, and renders correctly in the terminal.
