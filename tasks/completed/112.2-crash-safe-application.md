# Objective
Integrate recovery journals into proposal application so interruption cannot
leave mixed canonical state.

# Scope
* journal creation before canonical mutation
* stage complete intended target content
* preserve required pre-apply state
* phase-aware application
* target installation
* generated ownership installation
* proposal metadata commit
* ordinary-exception rollback
* unresolved transaction blocks new apply
* deterministic fault-injection checkpoints
* support multiple changed paths
* support generated file creation
* support generated file replacement
* support managed-block replacement

# Required invariants
proposal is not marked applied before target and ownership writes complete
ownership never claims content that was not installed
each target is either its old complete state or new complete state
interrupted application is detectable
new apply refuses unresolved recovery state
SQLite is not required

# Non-goals
* MCP recovery tool
* startup recovery orchestration
* SQLite refresh
* full machine power-loss guarantee
* unrelated lifecycle refactoring

# Required tests
Include:
`test_apply_writes_prepared_journal_before_mutation`
`test_apply_refuses_unresolved_transaction`
`test_fault_after_first_target_never_leaves_mixed_state`

`test_fault_after_ownership_install_preserves_recoverable_state`
`test_fault_before_proposal_commit_preserves_recoverable_state`
`test_ordinary_exception_restores_original_state`
`test_multi_target_application_uses_one_transaction`
