# Objective
Provide typed, deterministic SQLite-only proposal summary queries.

# Dependencies
LIFEOS-107.1 and LIFEOS-107.2.

# Scope
Add an immutable summary model:
```python
@dataclass(frozen=True)
class ProposalSummary:
    id: str
    status: ProposalStatus
    title: str
    created_at: str
    updated_at: str
```
Add:
```python
def list_proposals(
    connection: sqlite3.Connection,
    *,
    status: ProposalStatus | None = None,
) -> tuple[ProposalSummary, ...]:
    ...
```
Use deterministic ordering, preferably: `ORDER BY updated_at DESC, id ASC`.

Add:
```python
def count_proposals_by_status(
    connection: sqlite3.Connection,
) -> Mapping[ProposalStatus, int]:
    ...
```
Use the authoritative `ProposalStatus` type.

# Non-goals
* filesystem fallback
* automatic scanning
* ORM
* pagination
* lifecycle mutation

# Expected files
* `src/lifeos/registry/proposals.py`
* `tests/registry/test_proposals_index.py`

# Acceptance criteria
* deterministic ordering
* typed status filter
* correct empty result
* grouped counts are correct
* unknown database status produces a structured registry error rather than silently becoming an arbitrary string
* no filesystem reads occur during queries

# Focused test plan
* `tests/registry/test_proposals_index.py`: Verify SQLite query models correctly parse rows, filter by `ProposalStatus`, return empty tuples when no rows match, and throw structured errors on unknown database values.
