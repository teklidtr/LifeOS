# Objective
Prove that proposal registry state is fully disposable and reproducible.

# Dependencies
LIFEOS-107.1 through LIFEOS-107.5.

# Scope
Create end-to-end tests that:
1. create canonical proposal files
2. ensure only the intended proposals are Git-tracked in the test fixture
3. run the normal scan path
4. verify proposal rows
5. verify `lifeos proposals list`
6. verify `lifeos status`
7. delete the registry database
8. rebuild the registry through the normal initialization and scan path
9. verify identical proposal query and CLI results

Also test:
* untracked proposal ignored
* tracked proposal deletion reconciled
* lifecycle-status change reconciled
* malformed tracked proposal causes no partial proposal-table refresh

# Non-goals
* recovering Markdown from SQLite
* journal recovery
* LIFEOS-112 behavior
* performance benchmarking
* web dashboard

# Expected files
* Prefer a dedicated integration test file rather than making a unit-test file carry every layer.

# Acceptance criteria
* registry deletion loses no canonical information
* rebuilt query results equal the original results
* rebuilt CLI output is deterministic
* no SQLite value is treated as authoritative
* no canonical files are modified by rebuilding

# Focused test plan
* `tests/integration/test_proposals_rebuild.py` (or similar dedicated e2e file): End-to-end validation of the database's disposable nature. Construct real test files on disk, scan into SQLite, assert CLI outputs, delete `registry.db`, rescan, and assert exact output parity without data loss.
